# Bug 分类和优先级标准

## Bug 分类

### 按严重程度分类

#### 🔴 Critical（关键）
- **定义**：导致系统无法使用或数据丢失的问题
- **示例**：
  - 服务启动失败
  - 频繁崩溃
  - 数据损坏或丢失
  - 严重的安全漏洞
- **响应时间**：24 小时内
- **修复目标**：紧急发布补丁版本

#### 🟠 High（高）
- **定义**：严重影响核心功能但有临时解决方案
- **示例**：
  - 消息发送失败
  - 连接无法建立
  - 图片无法上传
  - 频道切换失败
- **响应时间**：3 天内
- **修复目标**：下一个补丁或小版本

#### 🟡 Medium（中）
- **定义**：影响用户体验但不阻塞核心功能
- **示例**：
  - UI 显示异常
  - 性能下降
  - 提示信息不准确
  - 兼容性问题
- **响应时间**：1 周内
- **修复目标**：下一个小版本

#### 🟢 Low（低）
- **定义**：轻微问题或改进建议
- **示例**：
  - 文案错误
  - 样式细节
  - 日志格式
  - 文档更新
- **响应时间**：按计划处理
- **修复目标**：合适的版本

### 按影响范围分类

#### 🌍 Widespread（广泛）
- 影响所有或大部分用户
- 在默认配置下可复现
- 跨平台/浏览器出现

#### 👥 Common（常见）
- 影响特定场景下的多数用户
- 在特定配置或操作下可复现
- 部分平台/浏览器出现

#### 👤 Edge Case（边缘情况）
- 影响少数用户或罕见场景
- 需要特殊条件才能复现
- 特定环境或配置下出现

### 按类型分类

- `bug:crash` - 崩溃或进程退出
- `bug:data` - 数据错误或不一致
- `bug:security` - 安全漏洞
- `bug:performance` - 性能问题
- `bug:ui` - 界面显示问题
- `bug:ux` - 用户体验问题
- `bug:compatibility` - 兼容性问题
- `bug:config` - 配置相关问题
- `bug:deployment` - 部署相关问题
- `bug:documentation` - 文档错误

## 优先级矩阵

| 严重程度 / 影响范围 | 广泛 | 常见 | 边缘情况 |
|---|---|---|---|
| **Critical** | P0 | P0 | P1 |
| **High** | P0 | P1 | P2 |
| **Medium** | P1 | P2 | P3 |
| **Low** | P2 | P3 | P3 |

### 优先级定义

- **P0**：立即处理，可能需要紧急发布
- **P1**：高优先级，纳入下一个版本
- **P2**：中优先级，按计划处理
- **P3**：低优先级，合适时处理

## Bug 生命周期

```
New → Triaged → In Progress → Fixed → Verified → Closed
  ↓      ↓           ↓           ↓        ↓
  └─ Invalid/Duplicate/Won't Fix → Closed
```

### 状态说明

1. **New**：新提交的 Bug，待分类
2. **Triaged**：已确认并分配优先级
3. **In Progress**：正在修复中
4. **Fixed**：已修复，待验证
5. **Verified**：已验证修复有效
6. **Closed**：已关闭

### 特殊标记

- `duplicate` - 重复的 Issue
- `invalid` - 无效的报告（非 Bug）
- `wontfix` - 不会修复（设计决策、超出范围等）
- `needs-info` - 需要更多信息
- `cannot-reproduce` - 无法复现

## Bug 分类流程

### 1. 接收阶段（24 小时内）

- [ ] 确认 Issue 描述清晰完整
- [ ] 验证能否复现
- [ ] 检查是否为重复 Issue
- [ ] 初步评估严重程度和影响范围

### 2. 分类阶段（3 天内）

- [ ] 确定 Bug 类型和优先级
- [ ] 添加相应标签
- [ ] 分配到 Milestone（如适用）
- [ ] 关联相关 Issue 或 PR

### 3. 处理阶段

- [ ] 根据优先级安排修复
- [ ] 修复后更新状态
- [ ] 添加测试用例防止回归
- [ ] 更新 CHANGELOG

### 4. 验证阶段

- [ ] 在修复版本中验证
- [ ] 确认原始报告者的场景已解决
- [ ] 检查是否引入新问题

### 5. 关闭阶段

- [ ] 标记为已验证
- [ ] 关闭 Issue
- [ ] 在 Release Notes 中说明

## 快速分类指南

### Critical Bug 快速识别

问自己以下问题：
1. 是否导致服务无法启动？ → Critical
2. 是否导致数据丢失或损坏？ → Critical
3. 是否存在严重安全风险？ → Critical
4. 是否影响所有用户的核心功能？ → Critical

如果以上都不是，继续评估：

### High Bug 快速识别

1. 是否阻塞核心使用场景？ → High
2. 是否导致功能完全不可用？ → High
3. 是否有简单的临时解决方案？ → 降为 Medium

### 边界情况处理

- **配置错误**：通常是 Low，除非默认配置有问题
- **文档缺失**：通常是 Low，除非导致严重误用
- **性能问题**：根据影响程度，Medium 到 Critical
- **兼容性问题**：根据影响用户比例，Low 到 High

## 示例

### 示例 1：消息发送失败

- **严重程度**：High（核心功能不可用）
- **影响范围**：Widespread（所有用户）
- **优先级**：P0
- **标签**：`bug`, `bug:data`, `priority:high`

### 示例 2：Safari 浏览器样式错乱

- **严重程度**：Medium（不影响功能）
- **影响范围**：Common（Safari 用户）
- **优先级**：P2
- **标签**：`bug`, `bug:ui`, `bug:compatibility`, `priority:medium`

### 示例 3：文档中的拼写错误

- **严重程度**：Low（不影响使用）
- **影响范围**：Widespread（所有读者）
- **优先级**：P3
- **标签**：`bug`, `bug:documentation`, `priority:low`

## 注意事项

1. **用户视角优先**：从用户影响而非技术复杂度评估优先级
2. **灵活调整**：特殊情况下可以调整优先级
3. **及时沟通**：重要 Bug 及时通知相关人员
4. **定期审查**：定期审查未处理的 Bug，调整优先级
5. **透明化**：在 Issue 中说明分类理由

## 1. 目标

把已经在主分支跑通的能力变成可安装、可对照文档使用的稳定 minor：

- 进程内 AI 网关
- `/admin` 值班台（总览、房间、聊天频道、人员席位）
- 房间 / 聊天频道 / IP 黑名单的配置覆盖层
- 席位禁言、请离、IP 黑名单
- Play/Agent 宿主与 `plays/echo/` 契约夹具

默认部署不变：无数据库、无账号、无 AI。`version: 1` 内存配置继续合法。Protocol v4 不升号。

完成门槛（路线图原句）：**实现有契约测试、准确文档和发布记录**。

## 6. 建议执行顺序

1. **补契约缺口**（工作包 A）：HTTP 人员 API、CHANGELOG、ADR-0005 调用方、排障与 Docker sqlite 说明。
2. **通读能力文档**（工作包 B）：admin / gateway / play / configuration 与三份示例 YAML，只改状态和与代码不符之处。
3. **跑验证**：`npm test` + 浏览器验收 + 三条产品路径。失败则修代码，再回到文档。
4. **入口与架构状态**（工作包 C、D）：仍先写「将随 v1.3 发布」，**不要先改徽章和 `package.json`**。
5. **打标签**（工作包 E）：改版本 → CHANGELOG 成 1.3.0 → README 徽章 → ROADMAP 状态表 → tag。
6. **发布后**：核对 GitHub Release、GHCR `1.3.0` / `1.3` / `1` / `latest`，把本文状态改为「已完成」并链到 CHANGELOG。

本地 `main` 目前比 `origin/main` 超前 2 个提交（管理页 favicon、输入框呼吸光晕），收口时一并纳入 1.3.0，不要当成无关改动丢掉。

## 7. 之后：v1.4 基建预告（不在本期做）

v1.3 发出后，基础设施下一刀是组装与身份，不是嵌入 SDK，也不是等狼人杀。

| 块 | 要立住的边界 | 先不要做 |
| --- | --- | --- |
| 功能目录 | 实例级：存储、身份接入、网关、已安装模块。频道级：图片/回复/回应/提及/输入提示/历史、访问权限、审核、玩法绑定。启动或保存时校验依赖；关闭的能力绕过 UI 仍拒绝。 | 四类预设可以后置；不要把规划字段提前写进当前 YAML 示例。 |
| 宿主身份 | 稳定用户 ≠ 会话 ≠ 连接 ≠ Agent 席位。宿主签发短期凭证，Pavilo 验证。保留访客但权限明确。权限覆盖发现/加入/历史/发送/玩法动作。 | 不自建注册找回；不做多租户；人员页在身份落地前继续只管理临时席位。 |

用一个「已有登录的普通产品接入预建频道」的最小示例驱动接口。嵌入页、治理闭环、SDK 分发放到 v1.5–v1.6。详细产品边界仍看 [集成设计](integration.md) 与 [ADR-0008](adr/0008-embeddable-composable-chat.md)。

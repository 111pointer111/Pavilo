# Pavilo v1.0 发布前完整路线图

本文档详细规划从 v0.3.0 到 v1.0 稳定版的所有必要工作。v1.0 的目标是建立一个**稳定、可靠、文档完善**的 ephemeral 聊天系统，为后续的 SQLite 持久化、Agent 集成等重量级功能打下坚实基础。

---

## 版本定位

### v1.0 的核心定义

> **一个极简、可靠、浏览器即用、默认无数据库的自托管网页聊天频道。**

### v1.0 必须保证

- ✅ 一键启动（npm start / Docker）
- ✅ 多频道支持
- ✅ 静态只读频道
- ✅ 消息 ACK、幂等、断线重连
- ✅ 资源上限和背压控制
- ✅ 严格配置验证
- ✅ 桌面/移动端可用
- ✅ 源码与容器部署
- ✅ CI/安全/文档/发布流程成熟
- ✅ Memory mode 行为稳定

### v1.0 明确不包含

- ❌ SQLite 持久化（v1.1+）
- ❌ 账号系统
- ❌ 角色权限
- ❌ 私聊
- ❌ 历史搜索
- ❌ Agent/LLM
- ❌ 插件市场

**这些缺失不是"没做完"，而是产品边界。**

## v0.4.0 — Security & Load Beta

**目标**：在 v1.0 之前把安全默认值和资源边界做实。

### 安全加固

#### 1. 重新评审 allowNoOrigin 默认值

**当前问题**：
- 代码默认 `allowNoOrigin: true`（允许非浏览器客户端）
- 对公网部署不够安全

**目标**：
- 修改代码默认值：`allowNoOrigin: false`
- 在启动日志中明确提示 Origin 检查状态
- 更新文档说明安全影响
- 添加迁移指南

**Breaking Change**：是（但 v0.x 允许）

#### 2. 威胁模型文档

创建 `docs/security/threat-model.md`，覆盖：

- **未认证访问**：任何人都能加入的风险与缓解
- **Origin 绕过**：如何正确配置 allowedOrigins
- **慢连接攻击**：backpressure 和超时机制
- **超大 payload**：各项大小限制的作用
- **图片解码**：客户端解码，服务端只存储
- **IP 隐私**：exposeMemberIps 的权衡
- **反向代理**：X-Forwarded-For 信任问题
- **配置泄露**：确保配置文件不被 HTTP 服务
- **资源耗尽**：内存、连接、频道限制

#### 3. 信任代理配置

**问题**：当前不处理 X-Forwarded-For

**目标**：
- 添加 `trustProxy` 配置选项
- 仅在显式配置时信任代理头
- 文档说明反向代理场景的 IP 获取

**配置示例**：
```yaml
server:
  trustProxy: false  # 默认值，不信任代理头
  # trustProxy: true  # 信任所有代理（不推荐）
  # trustProxy: ['127.0.0.1', '::1']  # 信任特定 IP
```

#### 4. HTTP 安全响应头

添加标准安全头：
```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Referrer-Policy: strict-origin-when-cross-origin
```

对于 WebSocket 连接，在 HTTP 升级前检查。

#### 5. 畸形输入测试

新增测试用例覆盖：
- 超大 JSON payload
- 畸形 WebSocket frame
- 无效 YAML 配置
- 特殊字符和 Unicode
- 嵌套深度攻击

### 压力与性能测试

#### 1. 建立 Benchmark 工具

创建 `tools/benchmark/`：
- `load-users.js` - 模拟大量用户同时在线
- `flood-messages.js` - 高频消息发送
- `slow-client.js` - 慢速客户端模拟
- `reconnect-storm.js` - 大量客户端同时重连
- `large-images.js` - 300KB 图片上传压测

#### 2. 性能基线测试

建立可复现的测试场景：
- **场景 1**：64 用户，4 频道，每频道 300 条消息
- **场景 2**：10 用户，1 频道，持续 1 小时聊天
- **场景 3**：5 个慢连接 + 10 个正常连接混合
- **场景 4**：频道 FIFO 淘汰（超过 maxChannelBytes）
- **场景 5**：大量图片（接近 maxChannelBytes 限制）

**指标**：
- 内存占用稳定性（无泄漏）
- 消息延迟（p50, p95, p99）
- CPU 占用
- 慢客户端隔离效果

#### 3. 压力测试文档

创建 `docs/testing/load-testing.md`：
- 如何运行 benchmark
- 如何解读结果
- 性能调优建议
- 已知瓶颈和限制

### 发布门槛

- ✅ allowNoOrigin 默认值收紧
- ✅ 威胁模型文档完成
- ✅ HTTP 安全头添加
- ✅ 畸形输入测试覆盖
- ✅ Benchmark 工具可运行
- ✅ 性能基线建立
- ✅ 无内存泄漏
- ✅ 慢客户端不拖垮正常客户端
- ✅ 所有资源上限可验证

v1.0 是 **ephemeral mode 的稳定版**，明确不包含：

# Play 契约（草案）

本文是玩法贡献的约束清单，不是 SDK。具体函数名在 v1.5 实现时再冻结。背景见 [evolution.md §11](evolution.md) 与 [ROADMAP v1.5](../ROADMAP.md)。

> 聊天页是「没有玩法」的默认频道投影。玩法不是在气泡上打补丁。

---

## 1. 产品模型

从管理员或用户看：**启用一套玩法模块，再把某个频道的 `play` 指过去**。进入该频道，加载该玩法自己的页面。聊天页仍是未绑定 `play` 的默认频道。

```yaml
channels:
  - id: general
    name: 大厅
    # 无 play → 现有聊天页
  - id: village
    name: 狼人杀
    play: werewolf   # 进入后打开 /plays/werewolf/?channel=village
```

同一玩法可以绑多个频道（多桌）：页面相同，`channel` 不同。

默认频道仍然是普通聊天。未启用任何玩法时，部署者看不到玩法页，启动成本不变。

---

## 2. 谁维护什么

| 能力 | 主线维护 | 玩法贡献者 |
| --- | --- | --- |
| 会话、Protocol v4、重连、离开 | 是 | 调用，不重写 |
| 频道列表切换（聊天页 ↔ 玩法页） | 是（薄宿主） | 不自己发明第二套房间系统 |
| `playAction` / `playState` 信封 | 是 | 填自己的 action 名与 payload |
| AI 网关、key、用量 | 是 | 只在服务端 host 里调用 |
| 规则状态机、提示词、Agent 工具 | 否 | 是 |
| 页面 DOM / CSS / 交互（投票、选人、夜间操作气泡） | 否 | 是 |
| 静态资源目录与 URL 约定 | 是 | 按约定放文件 |

主线不提供组件库、不规定必须用哪套颜色。官方狼人杀可以选用现有设计 token，社区玩法可以完全自己画。

---

## 3. 页面形态

每个玩法是**自己的 HTML 文档**，不是聊天页里的一块插槽。

理由：狼人杀需要选人、阶段操作、身份私密区，和聊天气泡流不是同一种界面；独立文档还能避免玩法 CSS 污染聊天页。

约定目录（实现时可微调，原则不变）：

```text
plays/werewolf/
  host.js          # 服务端：确定性状态机
  page/
    index.html     # 玩法页
    app.js
    style.css
```

- 页面地址：`/plays/<playId>/`，多桌用 `?channel=<channelId>`。
- 只服务该 `page/` 目录内的静态文件，不把仓库其他路径挂出去。
- 无会话时回到 `/` 登录；登录后的 session 与聊天页共用（`sessionStorage`）。
- 在聊天页点到玩法频道 → 跳到玩法页。在玩法页点到普通频道 → 回到 `/` 并切频道。不要在聊天气泡流里硬渲染玩法。

宿主（主线提供的脚本，玩法页引入）只做：

- 复用 `protocol` / `connection` / 会话恢复；
- 可选顶栏：房间名、频道切换、连接状态、离开、语言；
- `playAction(name, payload)` 与 `playState` 订阅。

玩法页拥有其余全部主区域。可以有自己的弹层、选人器、阶段时间轴。公开讨论若仍用该频道的消息事件，**由玩法自己决定怎么画**，不必复用 `messages.js`。

---

## 4. 协议与安全

- 同一条 WebSocket、同一个 Protocol v4。不为每个玩法开一版协议。
- 浏览器**禁止**直连 AI 网关。模型调用只发生在服务端 host。
- 浏览器发出的 `playAction` 仍是 Protocol v4 命令：transport → core 分发给该频道的 play host。host 校验非法动作后，只能再走 Command API 产生消息或 `playState`，不能自己写 Store、不能自己碰 socket。
- 私密信息（狼人队友、预言结果）只发给当事 peer，不要广播。
- 公开发言走现有 `message` 命令，从而沿用长度、频率、审核 Policy。
- 玩法页是 trusted code，与扩展相同：只加载管理员启用的目录，不从公网拉未知脚本。

---

## 5. 官方仓库额外要求

自己实例加载的玩法可以更自由。要进主仓库，还需要：

- 简体中文 + 英语文案；
- 移动端可用（主操作可点，不依赖纯 hover）；
- 玩法或 Agent 失败时，普通聊天频道仍可用；
- 有状态机测试：非法动作拒绝、局内记忆不泄漏到公开事件。

---

## 6. 现在不要做的

- 不要在 `chat.css` / `client/messages.js` 上堆狼人杀按钮；
- 不要做玩法商店、iframe 市场、前端框架强制；
- 不要做通用「组件平台」让所有玩法共用一套弹窗 API——选人气泡由该玩法自己写；
- 不要为尚未存在的玩法预留主题引擎。
